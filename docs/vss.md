# VSS

A `.vss` file is a package's styles: CSS after a short header. It sits beside the package's `.vs` and `.vsx` files and is compiled with them by `vsc`. A package's `.vss` files become one stylesheet, scoped to the elements the package's own markup makes.

```css
/* ui/kit/kit.vss */
package kit

@property --kit-accent { syntax: "<color>"; inherits: true; initial-value: #2563eb; }

.button {
    padding: 6px 12px;
    background: var(--kit-accent);
    &:hover { opacity: 0.9; }
}
```

This document says what `.vss` accepts, what `vsc` makes of it, and how it reaches the page. What is not written here is not supported.

---

## 1. The file

### 1.1 Header

A `.vss` file begins with its package, then any imports; comments and blank lines may come before and between them.

```css
package main

import "ui/kit"
import (
    "ui/theme"
    "ui/icons"
)
```

- The package is the folder's: a `.vss` file whose package differs from its folder's is refused.
- An import names a package whose styles come before this package's (§3.1), beside the packages the package's `.vs` and `.vsx` files import.

### 1.2 Body

Everything after the header is CSS, passed to the page's engine as written: selectors, nesting (`&:hover`, `& > header`), custom properties and `var()`, and at-rules (`@media`, `@supports`, `@keyframes`, `@font-face`, `@property`, `@import`, `@charset`).

---

## 2. What `vsc` checks

Each declaration in a style rule (also inside `@media`, `@supports`, `@layer`, `@scope`, `@container`) is checked against what the engine reads:

| Written | Result |
| :--- | :--- |
| a property the engine applies | accepted |
| a property it knows and does not apply yet | warning: `the engine does not apply 'x' yet: it will have no effect` |
| anything else | error: `unknown property 'colr'; did you mean 'color'?` |
| something that is not `name: value` | error: `expected a declaration, \`property: value\`` |
| a custom property (`--x`) | accepted, with any value |

The bodies of `@keyframes`, `@font-face`, `@property`, `@page`, `@counter-style` and `@font-feature-values` are not checked.

### 2.1 The document

A rule on the document is one whose every selector is a single compound of `:root`, `html` or `body` (`body.dark`, `:root[data-theme]`; not `body .x`).

Only package `main` sets properties there. In any other package, a declaration in such a rule that is not a custom property is an error: `only package main styles the document; a library may set custom properties here, not 'margin'`.

### 2.2 Tokens

A package's tokens are the custom properties it registers with `@property`, and those its rules on the document set.

- In a package other than `main`, an `@property` is named for the package: `--kit-…` in package `kit`. Otherwise: `a token of package kit is named --kit-…: custom properties share the page, so a library's carry its name ('--accent')`.
- An `@property` name not beginning with `--` is an error.
- A custom property named for a styled package the file sees -- its own, or one its package imports -- read with `var()` or set, must be one that package declares: `package kit declares no token --kit-acent; did you mean --kit-accent?`. A package may set new properties of its own name anywhere; what it reads has to be declared.

---

## 3. What `vsc` makes of it

### 3.1 The stylesheet

A package's `.vss` files, in file-name order, become one stylesheet:

```css
@property --kit-accent { … }                    /* @import, @charset, @font-face, @property: outside the layer */
@layer kit {
  :root { --kit-radius: 6px }                   /* rules on the document: in the layer, not the scope */
  @scope ([data-p="kit"]) to ([data-p]:not([data-p="kit"])) {
    .button { … }                               /* every other rule */
  }
}
```

`@media` and `@supports` are split the same way: their rules on the document stay outside the scope, under the condition; the rest go inside it.

The scope is the package's elements: `.button` above matches an element `kit`'s markup made, and nothing inside another package's element below it.

### 3.2 The generated source

`vsc` adds the stylesheet to the package as a generated declaration:

```vertex
// Generated by vsc from package kit's .vss files. Do not edit.
package kit

import __vss_component "ui/component"
import __vss_after0 "ui/theme"

public let __vssSheet = __vss_component.Sheet(package: "kit", css: "…", after: [__vss_after0.__vssSheet])

public enum Tokens {
    /// --kit-accent: <color>
    public static let Accent = __vss_component.Token(name: "--kit-accent", syntax: "<color>")
}
```

- `after` is the sheets of the imported packages that have `.vss` files (§1.1).
- In a package other than `main`, `Tokens` lists each `@property` the package registers, by its name without `--kit-` in `UpperCamelCase` (`--kit-text-color` is `TextColor`), with the `syntax` it gives (`*` where none). A `Token` has `Name` and `Syntax`.

---

## 4. How it reaches the page

### 4.1 Stamping

In a package with `.vss` files, every element its markup writes is stamped `data-p="<package>"` and carries the package's sheet. A call of another package's component (`<kit.Card>`) carries the calling package's sheet too, so a program whose markup is only another package's components still has its own styles applied.

### 4.2 Order

When a root is mounted, the runtime gives the page the sheets its elements carry: each after the sheets in its `after`, and package `main`'s last. A later sheet's layer wins over an earlier one's, so a package overrides what it imports, and the program overrides every package.

### 4.3 Theming

A program themes a package by setting its tokens: on the document in its own `.vss`,

```css
package main

import "ui/kit"

:root { --kit-accent: #10b981; }
```

or on an element, which reaches everything inside it:

```vertex
<div style={["--kit-accent": "rgb(0, 128, 0)"]}>
    <kit.Button label="Go" onPress={} />
</div>
```

Where nothing sets a token, its `@property` `initial-value` stands. In code, `kit.Tokens.Accent.Name` is `"--kit-accent"`.
